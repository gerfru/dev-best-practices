# Anti-Generic-AI Visual Design Checklist

Practice-based checklist (not academically sourced) for keeping visual design
in service of the information hierarchy established in the structural phase,
instead of defaulting to generic AI-generator / template-SaaS aesthetics.

---

## Signature Anti-Patterns to Avoid

| Anti-Pattern | Why it's a problem | Prefer instead |
|---|---|---|
| Oversized hero sections | Wastes prime screen space on non-functional content | Compact header with actual status/identity data |
| Cards for every piece of content | Turns unrelated info into visually equal blocks | Tables, lists, definition lists |
| Full dashboard built from floating rounded cards | No real hierarchy, all elements compete equally | Grouped sections with dividers, one primary focal area |
| Extreme border radius | Purely decorative, no functional signal | Small, consistent radius |
| Gradients without functional purpose | Decoration mistaken for branding | Flat color used for status/hierarchy only |
| Glassmorphism | Reduces legibility, purely decorative | Solid surfaces, real contrast |
| Decorative blobs / illustrations | No informational value | Omit, or use only where it teaches a concept |
| Icon before every heading | Adds noise, rarely aids recognition | Icons only for genuinely recognizable, frequent actions |
| Giant typography for ordinary content | Everything looks equally "important" | Typographic hierarchy proportional to actual importance |
| Repeated "Title + Subtitle + 3 Cards" sections | Generic template signature | Structure driven by actual content relationships |
| Fake metrics / filler stats | Misleads, adds no real information | Only show metrics the user actually needs |
| Excessive badges and pills | Visual noise, weak signal-to-noise ratio | Reserve for status that changes and matters |
| Layouts optimized for screenshots | Prioritizes marketing over daily use | Optimize for the person who uses this every day |

---

## Preferred Vocabulary for Professional / Enterprise UI

Typography · Alignment · Dividers · Lists · Tables · Tabs · Sidebars ·
Toolbars · Split Views · Inline Actions · Context Menus · Progressive Disclosure.

Use a card only when the content it wraps genuinely represents one distinct,
self-contained object — not as a default container for arbitrary content.

---

## Generic AI/SaaS Marketing-Page Signature

For content/marketing pages (not applications), the tell-tale generic structure is:

```text
Hero -> Logo Strip -> Three Feature Cards -> Statistics -> Testimonials -> CTA -> Footer
```

Prefer content-led composition: derive section structure and density from the
actual content and communication goal, not from this template.

## Design Systems Worth Consulting for Concrete Component Guidance

Material Design 3 · Apple Human Interface Guidelines · Microsoft Fluent ·
Atlassian Design System · IBM Carbon Design System · GitHub Primer ·
GOV.UK Design System.

These document not just what a component looks like, but when to use it and
when not to — more useful here than visual-inspiration galleries.
